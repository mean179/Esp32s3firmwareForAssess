# 舵机排针引脚速查（ottoRobot V1.1）

> 依据：卖家给的原理图 `IOs` 区（HDR1 / HDR3 / HDR4，PZ254-2-03-S）+ `CORE` 区（U2：ESP32-S3-N16R8）
> + 实物照片 + 原装舵机线颜色（棕 / 红 / 黄）。**“哪一列是哪个 SERVO”必须实测，见第 4 节。**

## 1. 每一列三针的身份（6 列都一样）

| 位置 | 颜色 | 网络名 | 电压 | 用法 |
|---|---|---|---|---|
| 外针（黄针的反面） | 棕 | **GND** | 0 V | ✅ LED 与按键都要接地 |
| 中间针 | 红 | **VBAT_IN** | **3.7 ~ 4.2 V**（1S 电池 / 充电电压） | ❌ **全程不接任何东西** |
| 内针 | 黄 | 舵机信号 = GPIO | 3.3 V 逻辑 | ✅ LED 信号 / 按键信号都接它 |

> 这块板的舵机口**没有引出 3.3 V**，只有“电池电压 + 地 + 信号”。
> 所以外接 LED 只能做成 **GPIO 高电平点亮**：`信号针 → 330 Ω → LED 长脚（阳极）→ LED 短脚（阴极）→ GND 针`。
> 千万不能把红色中针当 LED 正极：那是 4.2 V，接上就绕过了 GPIO 的控制，还有把 4.2 V 灌进 IO 的风险。

## 2. 最靠右侧、靠上的一组（黄针在下）

实物上这组三根针从上到下是 **棕 / 红 / 黄**，即：

| 行（从上往下） | 颜色 | 功能 |
|---|---|---|
| 第 1 行 | 棕 | GND |
| 第 2 行 | 红 | VBAT_IN（3.7–4.2 V）——不接 |
| 第 3 行 | 黄 | 信号 → 6 个候选 GPIO 之一 |

## 3. 最靠右侧、靠下的一组（黄针在上）

实物上这组从下到上是 **棕 / 红 / 黄**，所以从上往下是：

| 行（从上往下） | 颜色 | 功能 |
|---|---|---|
| 第 1 行 | 黄 | 信号 → 6 个候选 GPIO 之一 |
| 第 2 行 | 红 | VBAT_IN（3.7–4.2 V）——不接 |
| 第 3 行 | 棕 | GND |

> 两组方向相反（丝印标的“黄针总在内侧”），所以**不能靠“从上数第几根”直接套用另一组**。

## 4. 信号针只可能是这 6 个 GPIO

原理图里 6 个舵机网络分别接到模组的这些脚：

| 网络名 | GPIO | 模组脚号 | 备注 |
|---|---|---|---|
| SERVO1 | **IO17** | 10 | 无 strapping / USB / PSRAM 冲突，首选 |
| SERVO2 | **IO18** | 11 | 同上，首选 |
| SERVO5 | **IO8** | 12 | 可用 |
| SERVO6 | **IO12** | 20 | 可用 |
| SERVO3 | **IO39** | 32 | 属 JTAG 组（MTCK），做普通 IO 也能用 |
| SERVO4 | **IO38** | 31 | 可用 |

### 为什么不能从图纸直接说“这一列是 SERVO 几”
原理图只规定了“网络名 → 模组脚”，一列排针到底接哪个网络，取决于 PCB 布线，
丝印上只有 `上腿下足` / `扩展舵机` / `右手 左手` 这类功能名，没有 GPIO 号。
没有万用表时，用 `tools/pin_scan` 一分钟就能测出来（第 5 节）。

## 5. 实测步骤（不需要万用表）

```powershell
$env:IDF_TOOLS_PATH = 'C:\APPs\ESPIDF'
& 'C:\APPs\ESPIDF\frameworks\esp-idf-v5.5.5\export.ps1'
cd tools\pin_scan
idf.py set-target esp32s3
idf.py -p COMx flash monitor
```

1. **只接 LED**（一列：信号针 → 330 Ω → LED 长脚，短脚 → 该列 GND 针），在监视器里按回车。
   工具依次驱动 6 个候选，第 i 个闪 i 下并打印编号 → **LED 闪几下，这一列就是那个 GPIO**。
2. **再接按键**（另一列：信号针 + GND 针），按回车。
   读取模式下列出所有候选，**按下时 1 → 0 的那一行就是按键脚**。

> 顺序不能反：扫描阶段会把引脚驱动成输出，此时按键若接在同一脚上，按下等于把输出短接到 GND。

## 7. 实测记录（已填）

用 `tools/pin_scan` 在实物上测（2026-11-28，COM4，ESP-IDF v5.5.5）：

| 项目 | 列位置 | 实测现象 | 实测 GPIO |
|---|---|---|---|
| LED | 最右侧靠上那组的某一列 | 闪 **1** 下 | **GPIO17**（SERVO1，模组脚 10） |
| 按键 | 最右侧靠下那组的某一列 | 按下时 1 → 0 | **GPIO39**（SERVO3，模组脚 32） |

结论：**上组那一列 = SERVO1 = IO17，下组那一列 = SERVO3 = IO39**。
所以“上组=腿/下组=手”这类丝印推断不能直接当引脚表用，还是得测。

> 顺带解释一个容易误判的现象：`pin_scan` 扫完会把引脚切回“输入 + 上拉”，
> 45 kΩ 上拉会漏 ~30–100 µA 过 LED，看起来是**微亮常亮**（比正常点亮暗很多）。
> 这是工具的行为，不是 LED 坏了、也不是接错线。主固件里 LED 脚是推挽输出，
> 熄灭时是真正的 0 V，不会有这点微光。

## 8. 安全红线（贴板子旁边那种）

1. 红色中针（VBAT 3.7–4.2 V）**不许接 GPIO、不许接 LED 阳极、不许接按键**。建议用胶带把这一行贴住。
2. 接线前先断电（拔 USB），接完目视检查没有相邻针短接再上电。
3. 按键接线只在“输入上拉”阶段进行；扫描输出阶段不要按按键。
4. 一旦闻到异味 / 板子发烫 / 串口掉线，立刻拔 USB。
